# MRDVS 手持采集网页控制台设计

## 1. 目标与范围

在鲁班猫上部署一个面向手机使用的网页控制台。设备开机后可自动创建 Wi-Fi 热点并启动网页服务，用户通过网页启动或停止 MRDVS 原始驱动、选择是否完整录制全部 ROS 2 话题、查看点云与 IMU、管理和下载数据包，并配置下次开机是否继续自动启动热点与网页服务。

首版只控制 MRDVS 原始驱动，不启动 FAST-LIO2、FAST-LIVO2 或 PGO。代码以本仓库为唯一源文件，部署到鲁班猫独立目录 `/home/cat/mrdvs_collector`，并在 ARM64 环境安装和验证。

## 2. 已确认的目标平台

- 设备：LubanCat，主机名 `lubancat`，用户 `cat`。
- 系统：Ubuntu 24.04.4 LTS，`aarch64`。
- ROS：ROS 2 Jazzy，已安装 `rclpy`、`rosbag2`、MCAP 和 SQLite3 存储插件。
- MRDVS SDK：已安装在 `/opt/MRDVS`。
- ROS 工作空间：`/home/cat/mrdvs_ros2_ws`。
- 雷达：通过 `eth1` 连接，默认地址 `192.168.100.82`。
- 热点：使用 `wlan0`；无线网卡支持 WPA2、AP、2.4GHz 和 5GHz。
- 存储：内部系统盘与数据目录共用文件系统，检查时约有 94GB 可用空间。

## 4. 独立部署目录

网页采集工具不放入 `/home/cat/mrdvs_ros2_ws`，统一部署在：

```text
/home/cat/mrdvs_collector/
├── app/       # 网页后端、静态前端和部署版本信息
├── .venv/     # FastAPI/Uvicorn 专用 Python 虚拟环境
├── config/    # 用户可持久化配置
├── state/     # 运行状态和会话记录
└── bags/      # rosbag 数据包
```

程序升级只替换 `app/` 中的受版本管理文件，不删除 `.venv/`、`config/`、`state/` 或 `bags/`。现有 `/home/cat/mrdvs_ros2_ws` 只作为 MRDVS 驱动的 ROS 2 underlay；网页服务启动时加载其 `install/setup.bash`，但网页源码和运行数据不写入该工作空间。

只有 systemd 单元和 NetworkManager 热点连接因 Linux 系统要求保存在系统目录，其他网页项目文件均收敛在上述独立根目录。

## 5. 总体架构

系统采用 Python FastAPI、Uvicorn 和 `rclpy`，前端资源全部随项目本地部署，不依赖互联网。核心组件如下：

1. **Web API**：提供状态、驱动控制、录包控制、设置和数据包管理接口。
2. **ROS 数据桥**：订阅点云和 IMU，只为网页生成抽样显示数据，通过 WebSocket 推送。
3. **进程管理器**：以固定参数启动和停止 MRDVS launch 与 rosbag，管理独立进程组和退出状态。
4. **数据包管理器**：校验名称和路径，统计大小，流式下载，二次确认删除，并监控磁盘空间。
5. **系统辅助程序**：以严格白名单提供热点配置以及 systemd 自启开关，不接受任意 Shell 命令。
6. **静态前端**：使用本地打包的 Three.js 显示三维点云，使用本地图表组件显示 IMU。

网页后端以普通用户 `cat` 运行。只有 NetworkManager 和 systemd 所需的少量操作通过 root 拥有、参数受限的辅助程序执行。

## 6. systemd 与热点生命周期

使用以下单元组织开机启动：

- `mrdvs-collector.target`：热点和网页服务的组合启动目标，也是网页中“下次开机自动启动”开关控制的唯一对象。
- `mrdvs-hotspot.service`：启动 NetworkManager 热点连接，并在退出时恢复普通 Wi-Fi 选择。
- `mrdvs-web-console.service`：在热点地址可用后，以 `cat` 用户启动网页后端和 ROS 数据桥。

NetworkManager 热点连接名为 `mrdvs-hotspot`，设置 `connection.autoconnect=no`。热点只能由采集 target 主动拉起，不会在 target 被禁用后自行抢占 `wlan0`。原有普通 Wi-Fi 配置不删除、不禁用；当下次开机不启动采集 target 时，NetworkManager 自动连接已保存且允许自动连接的普通 Wi-Fi。

网页关闭“下次开机自动启动”时只禁用 target，不停止当前热点、网页、驱动或录包。热点名称和密码修改后在下一次热点启动时生效，避免当前浏览器连接突然断开。系统提供终端恢复命令，用于在网页自启关闭后重新启用 target。

网页仅监听 `10.42.0.1:80`。服务仍以普通用户运行，只授予绑定低端口所需的最小 capability，不在雷达网口或普通 Wi-Fi 地址上开放管理页面。

## 7. 驱动与录包状态机

核心状态为：

```text
空闲
  -> 录包预备（可选）
  -> 驱动启动中
  -> 驱动运行中 / 驱动运行且录制中
  -> 停止中
  -> 空闲或错误
```

驱动使用现有入口：

```text
ros2 launch lx_camera_ros lx_lidar_ros.launch.py
  ip:=192.168.100.82
  enable_rviz:=false
  imu_angular_range_level:=<配置值>
```

如果用户在启动驱动前选择“同时录制”，系统先启动完整录包并等待 rosbag 进入就绪状态，再启动驱动，使 rosbag 能从第一个被发现的驱动话题开始接收。驱动已运行时也可以单独开始或停止录制，此时只保存录制按钮按下之后的数据。

停止整个会话时先停止驱动，让最后的 ROS 消息进入录包，再向 rosbag 发送 `SIGINT` 并等待其写完 MCAP 索引和 `metadata.yaml`。重复启动、并发停止、录制中删除当前包等非法状态转换由后端拒绝。

浏览器断开或刷新不改变后台状态。驱动异常退出时系统自动正常结束录包、保留已写数据、清理残留进程并记录错误。现有 MRDVS 驱动在用户主动关闭时可能返回 `-6`；如果停止动作由用户发起且已确认没有残留进程，该结果按“已停止并带关闭警告”处理，不误判为仍在运行。

## 8. 完整录包约束

录包使用独立进程执行等价于以下命令的固定参数调用：

```text
ros2 bag record --all --include-hidden-topics --storage mcap --output <安全目录>
```

录包不做抽样、不做话题过滤、不修改消息内容，也不改写驱动时间戳。必须保留：

- `PointCloud2.header.stamp`；
- 每个点自带的 `timestamp` 字段；
- `Imu.header.stamp`；
- 驱动启动后发现的其他全部普通和隐藏 ROS 2 话题及其完整消息字段。

网页点云抽样来自独立的 `rclpy` 订阅副本，只影响通过 WebSocket 发送给浏览器的数据。WebSocket 拥塞时允许丢弃旧的显示帧，绝不对 rosbag 进程施加采样或背压。

录制期间持续检查数据包写入状态和文件系统剩余空间。可用空间低于 5GB 时，系统向 rosbag 发送正常停止信号、等待元数据落盘，并显示明确告警。突然断电无法保证最后一小段缓存数据，但 MCAP 文件应保留并可使用 ROS 2 工具检查或重建索引。

## 9. 数据包命名、下载与删除

用户必须在网页中填写数据包名称，不自动使用时间戳替代。名称规则如下：

- 不能为空；
- 允许中文、英文字母、数字、短横线和下划线；
- 去除首尾空格；
- 禁止 `/`、反斜杠、`..`、控制字符和路径分隔符；
- 已存在同名目录时拒绝覆盖。

默认保存路径为 `/home/cat/mrdvs_collector/bags/<用户名称>/`。数据包根目录可以在设置页修改，但后端只允许使用已配置并通过权限、可写性和空间检查的绝对目录。所有列表、下载和删除操作都在解析真实路径后再次确认目标仍位于该根目录内。

数据包页面显示名称、状态、大小、持续时间和创建时间。完成的数据包通过 HTTP 实时打包为 `.tar` 流下载，不在鲁班猫上额外生成同等大小的压缩副本。正在录制的数据包禁止下载和删除。删除操作需要二次确认，并再次核对当前状态和真实路径。

## 10. 实时可视化与页面布局

页面采用手机优先的响应式布局，包含：

- 顶部状态：热点、网页服务、驱动、录包、点云话题、IMU 话题和磁盘空间；
- 会话控制：数据包名称、是否随驱动同时录制、启动/停止驱动、开始/停止录制；
- 三维点云：旋转、缩放、视角复位、按强度着色、实际刷新率和显示点数；
- IMU：最近 10 秒的加速度 XYZ、角速度 XYZ、当前数值和实际话题频率；
- 日志：限制条数的驱动、录包和系统错误尾部日志；
- 数据包：列表、下载和二次确认删除；
- 设置：热点名称、热点密码、数据包根目录、雷达 IP、IMU 量程和下次开机自启开关。

点云桥按每帧最多 50000 点、最高 5Hz 下采样并发送紧凑二进制数据。IMU 最高 20Hz 推送，浏览器只保留最近 10 秒。所有前端 JavaScript、字体和图形资源本地提供，连接热点后无需互联网。

## 11. 安全与故障处理

- 不设置网页登录，访问边界依赖 WPA2 热点；后端同时限制监听地址、Origin 和允许的 API 参数。
- 不使用 `shell=True` 拼接用户输入；驱动和录包均通过参数数组启动。
- root 辅助程序只允许预定义子命令，并校验 SSID、密码、目录、布尔开关和数值范围。
- 系统服务使用独立进程组和 systemd cgroup；服务停止时先优雅退出，超时后再清理残留子进程。
- 后端启动时检查旧状态文件与真实进程，不能仅依赖上次保存的 PID。
- 驱动、录包、磁盘、话题和 WebSocket 分别维护状态，单个浏览器客户端异常不能中止采集。
- API 返回结构化错误码和中文错误信息；页面显示可操作的恢复建议及有限长度日志。
- 热点启动失败时退出采集 target，并允许 NetworkManager 恢复普通 Wi-Fi。

## 12. 代码边界

新增独立 Python 应用包 `mrdvs_web_console`，不把网页逻辑写入现有 C++ 驱动，也不把网页项目安装进现有 ROS 2 工作空间。应用通过系统 ROS 2 环境和现有工作空间 underlay 使用 `rclpy`、消息类型及驱动 launch。包内按职责拆分：

- 配置与输入校验；
- 驱动/录包进程管理；
- ROS 点云与 IMU 数据桥；
- 数据包和磁盘管理；
- FastAPI 路由与 WebSocket；
- 静态前端；
- systemd、NetworkManager 和安装资源；
- 单元、API 和 ROS 集成测试。

FastAPI/Uvicorn 安装到 `/home/cat/mrdvs_collector/.venv`，并通过 `--system-site-packages` 使用系统 ROS 2 的 `rclpy`。应用部署到 `/home/cat/mrdvs_collector/app`。虚拟环境、运行状态、运行日志、热点运行配置和数据包不提交 Git。

## 13. 部署与验收

部署前先验证本机可通过鲁班猫有线地址 `192.168.100.100` 建立 SSH 备用通道，再切换 `wlan0` 到 AP，避免热点测试导致远程失联。

验收必须覆盖：

1. 单元测试：名称/路径校验、状态机、进程退出、磁盘阈值和点云抽样。
2. API 测试：状态、控制、设置、下载、删除和非法状态响应。
3. ROS 集成测试：模拟点云/IMU 同时进入网页桥和完整 rosbag。
4. ARM64 构建与安装：鲁班猫原生构建成功，systemd 单元和 Python 依赖可用。
5. MRDVS 实机：原始驱动能发布点云、IMU、RGB 及其他预期话题。
6. 完整录包：用 `ros2 bag info` 检查全部话题、消息数和持续时间；读取消息确认点云字段与驱动时间戳未改变。
7. 下载：网页下载 `.tar` 后解包，MCAP 和元数据与源文件校验和一致。
8. 删除与保护：同名包、越界路径、录制中下载/删除、二次确认和低磁盘停止均符合设计。
9. 热点与移动端：客户端能连接 `MRDVS-Collector` 并通过 `http://10.42.0.1` 控制和查看数据。
10. 自启与恢复：启用时重启可恢复热点和网页；网页关闭下次自启后重启会连接已保存普通 Wi-Fi，并可通过 SSH 恢复采集 target。
11. 清理：测试结束后没有残留驱动、rosbag 或临时测试进程。

## 14. 非目标

首版不包含 FAST-LIO2、FAST-LIVO2、PGO 的启动控制，不提供公网访问、多用户权限、云端上传、在线修改 ROS 消息、自动删除旧数据包或视频转码。后续功能通过新的设计与实施阶段扩展。
